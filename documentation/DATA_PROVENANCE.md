# Data Provenance

## Data Source

This project uses synthetic healthcare records generated by **Synthea**, an open-source synthetic patient generator. Synthea produces realistic but fictional healthcare records, allowing healthcare data workflows and analytical methods to be explored without using actual patient records.

The source data was downloaded from the official Synthea downloads page:

- **Source website:** [Synthea Downloads](https://synthea.mitre.org/downloads)
- **Dataset:** 100 Sample Synthetic Patient Records, CSV
- **Dataset version:** Latest Version of Synthea
- **Download date:** November 12, 2026
- **Download format:** CSV files organized in a folder
- **Direct download:** [Synthea Sample Data – CSV](https://synthetichealth.github.io/synthea-sample-data/downloads/latest/synthea_sample_data_csv_latest.zip)

The downloaded dataset contains individual CSV files organized within a folder. The original source files are retained in `data/raw/` to preserve the data used in the project.

## Data Processing and Transformation

The raw source tables were loaded into a Microsoft Fabric Lakehouse and organized using a Bronze, Silver, and Gold data architecture.

### Bronze Layer

The Bronze layer contains the original source data. These tables preserve the raw records and serve as the starting point for downstream processing.

### Silver Layer

The Silver layer contains cleaned and enriched data used for analysis.

The medication records are combined with patient demographic information to calculate patient age at the time a medication was recorded. Records are assigned to age groups, and payer information is incorporated to support comparisons across insurance providers.

A calculated uncovered-cost field is also used during processing:

```python
calculated_uncovered_cost = total_cost - payer_coverage
```

This is a derived measure of the portion of recorded medication cost not covered by the payer. It should not be interpreted as verified patient out-of-pocket spending.

### Gold Layer

The Gold layer contains structured tables and aggregations designed for analysis and visualization.

The final analysis combines medication cost and payer coverage information by age group and payer.

## Final Processed Dataset

The final processed dataset is:

`data/processed/cleaned_aggregated_data.csv`

It is derived from the final age-group and payer coverage aggregation produced by the project pipeline.

The dataset contains the following fields:

| Field | Description |
|---|---|
| `age_group` | Patient age category calculated at the time the medication record began |
| `payer_id` | Unique identifier for the insurance payer |
| `payer_name` | Name of the insurance payer |
| `medication_records` | Number of medication records included in the aggregation |
| `total_medication_cost` | Sum of medication costs within each age group and payer combination |
| `total_payer_coverage` | Sum of payer-covered medication costs within each age group and payer combination |
| `coverage_proportion` | Proportion of total medication costs covered by the payer |

Each row represents one combination of age group and payer.

The `coverage_proportion` field is calculated as:

```python
coverage_proportion = total_payer_coverage / total_medication_cost
```

It is represented as a decimal ratio. For example, `0.29` represents 29% coverage. If total medication cost is zero, the proportion is undefined and may be null.

## Data Integrity and Interpretation

The project retains the original raw CSV files separately from the processed output to distinguish source data from derived data.

The final dataset reflects the transformations and aggregation logic implemented in the project pipeline. Results should be interpreted within the limitations of the synthetic source data and the definitions of the calculated fields.

In particular:

- Age is calculated at the time a medication record begins, not based on a patient's current age.
- Medication record counts do not represent distinct medications or unique patients.
- Costs not covered by a payer should not automatically be interpreted as actual patient out-of-pocket expenses.
- Coverage proportions represent payer coverage of recorded medication costs, not a patient's overall insurance coverage.

For field-level definitions of the raw source files and final processed dataset, refer to `data/DATA_DICTIONARY.md`.
